# 舱单数据定义

id是主单、分组单或箱货明细唯一字符串编号，parent为空表示主单。节点申报件数、净重和毛重是其完整子树的申报总量，校验时只加直接子节点，避免多层重复计数。包装carton=1件，pallet=10件；重量kg与t统一为kg。件数必须非负整数，净重非负且毛重不得低于净重。
拆并结构采用每节点最多一个父级的有向图；自环、长环、缺父级均阻断封存，保留环路径。不会以平面求和替代逐层校验。
危险品按明确分类与UN编号检查，3类与5.1类禁止同箱；未知分类和缺失编号需复核。此演示规则只覆盖文中三类，不替代运输合规审批。
报关总量只汇总主单，与context.json内的申报件数、净重和毛重逐项比较。重复同值折叠，重复编号冲突全部隔离。原始计数=采纳+隔离+空行+重复表头+重复同值行。
封存需所有图、重量、危险品和采信问题处理完毕。数值均Decimal，对外字符串保留精度，编号不转整数。

## 通知签收（M8）

通知按批次（batch_id）发布，通知编号 `N-{批次}-V{版本号}`，版本号在批次内递增。通知携带两张主单指纹：拆并关系指纹取主单整棵子树的有向边序列，重量指纹取子树件数、净重、毛重合计。新修订与上一成功发布逐张主单比对，关系变化优先于重量变化归类；指纹不变即整批重发（RESEND）。

当前依据只认最近一次实质覆盖该主单的成功发布：受影响主单以新通知为依据，未受影响主单继续沿用旧通知，重发通知不替代任何依据。发布失败的通知保留未送达记录但不作为依据，当前依据恢复为上一版；失败未重试前禁止发布新修订。签收按 (批次,主单,依据通知) 唯一，同一通知重试幂等不新增第二套签收；依据被替代后旧签收行保留为失效审计，须按新通知重签，未持有效签收的主单不可申报。

裁决：无受影响主单为整批统一签收（重发沿用既有签收）；部分主单受影响为受影响主单先行签收；全部主单受影响或有主单被拆并删除为整批统一签收。接收方取自 context.receivers，缺省回落报关行默认签收岗。
